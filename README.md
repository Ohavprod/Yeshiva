# אתר ישיבה תיכונית עפולה

## מבנה הפרויקט
- `index.html` — האתר הציבורי (בית, עדכונים רצים, גלריה, אודות)
- `staff.html` — כניסת צוות + לוח בקרה (מחנך / מנהל / מנהל מערכת)
- `approve.html` — עמוד ציבורי לאישור טיול, נפתח מקישור ששולח המחנך
- `assets/` — עיצוב, לוגו, וחיבור ל-Supabase
- `supabase/functions/create-staff-user` — הפונקציה שיוצרת חשבונות צוות (מנהל בלבד)

## איך להעלות לאוויר (GitHub Pages, כמו שאתה רגיל)
פשוט להעלות את כל התיקייה כמו שהיא ל-repo ולהפעיל GitHub Pages — אין build step, הכל HTML/CSS/JS סטטי.

## הקמת המשתמש הראשון (מנהל מערכת)
כדי שלא יהיה "עוף/ביצה" (רק מנהל יכול ליצור משתמשים, אבל עדיין אין אף מנהל) —
המשתמש **הראשון** שנרשם במערכת הופך אוטומטית למנהל מערכת. הדרך הכי נקייה ליצור אותו:

1. כנסו ל-Supabase Dashboard של הפרויקט → **Authentication → Users → Add user**
2. הזינו את המייל והסיסמה שלכם, ולחצו "Auto Confirm User"
3. היכנסו עם הפרטים האלו דרך `staff.html` — תקבלו אוטומטית הרשאת מנהל מערכת
4. מרגע זה, כל שאר אנשי הצוות (מחנכים, מנהלים) נוצרים דרך "ניהול משתמשים" בתוך המערכת עצמה

## איך נוצר משתמש צוות חדש
מנהל המערכת ממלא טופס ב"ניהול משתמשים" (שם, מייל, תפקיד, כיתה) → נשלח קישור הזמנה
(נוצר על ידי Edge Function מאובטח בשם `create-staff-user`) → יש להעתיק את הקישור ולשלוח
אותו לאיש הצוות (וואטסאפ/מייל) → בפתיחת הקישור הוא יוגדר סיסמה אישית ויכנס למערכת.

## איך עובד תהליך אישור הטיול
1. מחנך יוצר טיול, בוחר תלמידים ולוחץ "שליחת קישור אישור"
2. נוצר קישור קבוצתי אחיד (`approve.html?t=...`) — ניתן לשתף בקבוצת ההורים של הכיתה כפי שהוא,
   וכל הורה יאשר את הילד/ה שלו מתוך הרשימה
3. לחלופין, לצד כל תלמיד יש כפתור "שליחת וואטסאפ" שפותח הודעה אישית מוכנה עם קישור אישי
   (`&s=<student_id>`) שמציג ישירות את הילד הרלוונטי
4. המחנך רואה בזמן אמת מי אישר ומי לא, ויכול לשלוח תזכורת באותו אופן

## נקודות אבטחה חשובות
- כל הרשאה נאכפת בצד השרת (Row Level Security ב-Supabase) — לא רק בממשק
- מפתח ה-Supabase שבקוד הוא מפתח "anon" ציבורי לפי התכנון של Supabase, מיועד לרוץ בדפדפן
- עמוד ההורים (`approve.html`) לא חושף מספרי טלפון או מידע רגיש — רק שם התלמיד/ה ופרטי הטיול,
  דרך פונקציה ייעודית בשרת
- הרשמה עצמית (ללא הזמנת מנהל) עדיין אפשרית טכנית מול ה-API הציבורי; כל מי שנרשם כך מקבל
  role="pending" ואין לו כל גישה עד שמנהל מערכת ישייך לו תפקיד. אם תרצה לחסום הרשמה עצמית
  לגמרי, אפשר לכבות "Email signups" בהגדרות ה-Authentication ב-Supabase ולהשאיר רק את זרימת
  ההזמנות

## מה שנשאר לך להוסיף בהמשך (אם תרצה)
- **גלריה אמיתית**: כרגע הגלריה היא placeholder בעיצוב, ללא ניהול תמונות. כדי לאפשר
  להעלות תמונות אמיתיות דרך המערכת אפשר להוסיף Supabase Storage — זו תוספת קטנה יחסית
- שיוך "מחנך/ת" לכיתה בטבלת הכיתות עצמה (`classes.homeroom_teacher_id`) — קיים במסד הנתונים
  אך עדיין אין לו ממשק עריכה נפרד
